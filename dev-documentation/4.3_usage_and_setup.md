## Part 1 — Developer Setup (What You Need to Do Before Deploying)

### Step 1 — Generate a JWT Secret Key

This is the most critical secret.  Run this **once** and save the output:

```bash
python -c "import secrets; print(secrets.token_hex(32))"
# OR
openssl rand -hex 32
```

Example output: `a3f8c1d9e2b7...` (64 hex characters)

Store this as `SECRET_KEY` in:
- **Render** → Environment Variables → `SECRET_KEY`
- **Local** → `.env` file

---

### Step 2 — Set Up Stripe (takes ~10 minutes)

#### 2a. Create a Stripe account

1. Go to [dashboard.stripe.com](https://dashboard.stripe.com) and sign in.
2. Make sure you are in **Test mode** (toggle in the top left).

#### 2b. Create a product and price

1. Sidebar → **Product catalog** → **Add product**
2. Name: `FinSight Pro`
3. Pricing: **Recurring** → `MYR 29.00` / month
4. Save the product.
5. On the product detail page, copy the **Price ID** — looks like `price_1...`

#### 2c. Get your API keys

1. Sidebar → **Developers** → **API keys**
2. Copy the **Secret key** (`sk_test_...` for test, `sk_live_...` for production)

#### 2d. Set up the webhook endpoint

**For production (Render):**
1. Sidebar → **Developers** → **Webhooks** → **Add endpoint**
2. URL: `https://your-render-backend.onrender.com/webhooks/stripe`
3. Events to listen to:
   - `invoice.payment_succeeded`
   - `customer.subscription.deleted`
4. After saving, click **Reveal** next to "Signing secret" — copy `whsec_...`

**For local development:**

Install the Stripe CLI:
```bash
# macOS
brew install stripe/stripe-cli/stripe

# Windows
scoop install stripe
# OR download from: https://github.com/stripe/stripe-cli/releases
```

Forward webhooks to your local backend:
```bash
stripe login
stripe listen --forward-to localhost:8000/webhooks/stripe
# The CLI prints: "Your webhook signing secret is whsec_..."
# Copy that value into .env as STRIPE_WEBHOOK_SECRET
```

To trigger a test payment event:
```bash
stripe trigger invoice.payment_succeeded
```

### Step 4 — Run the Database Migration

After pushing the code and the backend redeploys on Render, the new auth
tables (`users`, `refresh_tokens`, `api_keys`) are created automatically
because `main.py` calls `Base.metadata.create_all(bind=engine)` on startup.

If you prefer Alembic migrations (recommended for production):
```bash
cd src/backend
pip install -r requirements.txt
alembic upgrade head
```

---

### Step 5 — Create Your First Admin Account

The system has no admin accounts by default.  After deploying:

1. **Register a normal account** via the frontend at `/auth/register`, or via curl:
   ```bash
   curl -s -X POST https://your-render-url.onrender.com/auth/register \
     -H "Content-Type: application/json" \
     -d '{"email": "admin@yourcompany.com"}' | python -m json.tool
   ```
   Copy the `generated_password` — you only see it once.

2. **Manually promote to admin** via the database.
   In Supabase SQL editor or Render Postgres console:
   ```sql
   UPDATE users SET role = 'admin' WHERE email = 'admin@yourcompany.com';
   ```

3. That's it.  The admin user can now access `/admin/dashboard` in the frontend
   and all `GET/PATCH/DELETE /admin/users/**` backend routes.

## Part 2 — User Guide (How to Use the App)

### As a New / Free User

#### Registering

1. Navigate to `https://your-app.vercel.app/auth/register`
2. Enter your email address and click **Create account**.
3. A modal appears showing your generated password:

   ```
   K7hXqN2-Rv8pzYoLmTcAeD_fG3h
   ```

4. **Copy it immediately** — click the "Copy" button. It will never be shown again.
5. Click "I've saved my password — go to login".

#### Logging In

1. Navigate to `/auth/login`.
2. Enter your email and the password you copied.
3. You are redirected to the dashboard.

#### What Free Users Can See

- Public landing page at `/`
- All company profiles at `/companies` and `/companies/[TICKER]`
- Free-tier charts: Revenue Trend, Income Bar, Margin Chart
- KPI cards (EPS, P/E ratio, ROE, etc.)
- Your account settings at `/account`

#### What Free Users Cannot See

- `/dashboard` → redirected to `/upgrade`
- Advanced charts (Sentiment Overlay, Peer Radar, Waterfall)
- Developer API key
- POST /search endpoint (returns 403)

#### Upgrading to Pro

1. From `/account`, click **"View pricing →"**, or navigate directly to `/upgrade`.
2. On the pricing page, click **"Upgrade to Pro →"**.
3. You are redirected to the Stripe-hosted checkout page.
4. Enter your card details (use Stripe test card `4242 4242 4242 4242` in test mode).
5. After payment, Stripe sends a webhook to the backend, which automatically:
   - Upgrades your role to `paid`
   - Generates your developer API key
6. You are redirected back to `/account?upgraded=true`.
7. Your account page now shows your API key prefix and the paid tier badge.

#### Using the Pro Dashboard

1. Navigate to `/dashboard` — you now see all 8 company tiles.
2. Click any company (e.g. `MAYBANK`) to go to `/dashboard/MAYBANK`.
3. You see three paid-tier visualisations:
   - **LLM Sentiment Overlay** — AI sentiment vs revenue trend
   - **Peer Comparison Radar** — 5-axis competitive comparison
   - **Revenue Waterfall** — revenue → gross profit → operating income → net income

#### Using Your Developer API Key

1. From `/account`, your key prefix is shown (e.g. `fsk_K7hX…`).
2. Use it in any HTTP client:

   ```bash
   curl -H "X-API-Key: fsk_yourFullKeyHere" \
     -X POST https://finsight-api.onrender.com/search \
     -H "Content-Type: application/json" \
     -d '{"ticker": "MAYBANK", "statement_type": "kpi"}'
   ```

   ```python
   import httpx
   res = httpx.post(
       "https://finsight-api.onrender.com/search",
       json={"ticker": "CIMB", "statement_type": "balance_sheet", "fiscal_year": 2023},
       headers={"X-API-Key": "fsk_yourFullKeyHere"},
   )
   print(res.json())
   ```

3. To rotate your key (if exposed): go to `/account` → click **"Rotate key"**.
   - Your old key is immediately revoked.
   - The new raw key is shown once — copy it immediately.

#### Logging Out

From `/account`, click **"Sign out"** at the bottom.

## Part 3 — Admin Guide

### Accessing the Admin Dashboard

1. Log in with your admin account at `/auth/login`.
2. Navigate to `/admin/dashboard` (hidden route — not linked in the public nav).
3. You see a table of all registered users.

### User Management Actions

#### Upgrading a User Manually

If a user's Stripe payment succeeded but the webhook failed:
1. Find the user in the table.
2. Click the role dropdown next to their row.
3. Change from `free` → `paid`.
4. The change takes effect immediately.

The user still needs to generate their API key manually via `/account`, or
you can trigger a fresh webhook event in the Stripe dashboard.

#### Deactivating a User

Click the **"Active"** button in the user's row — it toggles to **"Inactive"**.
A deactivated user cannot log in until reactivated.

#### Deleting a User

Click **"Delete"** in the user's row and confirm the prompt.
This permanently removes the user and all their refresh tokens and API keys
(cascaded by the database FK constraints).

#### Revoking an API Key

There is no direct "revoke key" button in the admin UI (by design — the user
rotates their own key).  To revoke programmatically:

```bash
# Using the admin's session cookie — run from a logged-in curl session
# Or use the Supabase SQL editor:
UPDATE api_keys SET revoked = true WHERE user_id = <user_id>;
```

### Monitoring Stripe Subscriptions

The user table shows the `stripe_subscription_id` column (truncated).
To see full subscription details, open the Stripe dashboard and search by
the subscription ID or the user's email.

## Part 4 — Local Development Quick Start

```bash
# 1. Clone and install backend deps
cd src/backend
pip install -r requirements.txt

# 2. Copy and fill in .env
cp .env.example .env
# Edit .env: add SECRET_KEY, STRIPE_SECRET_KEY, STRIPE_WEBHOOK_SECRET

# 3. Start PostgreSQL (Docker)
docker compose up -d db

# 4. Run migrations
alembic upgrade head

# 5. Start backend
uvicorn main:app --reload --port 8000
# API docs: http://localhost:8000/docs

# 6. In another terminal — start frontend
cd frontend
npm install
npm run dev
# Frontend: http://localhost:3000

# 7. In another terminal — forward Stripe webhooks
stripe listen --forward-to localhost:8000/webhooks/stripe
# Copy the whsec_... value into .env as STRIPE_WEBHOOK_SECRET, restart backend

# 8. Run the test suite
cd ..   # back to repo root
FINSIGHT_BASE_URL=http://localhost:8000 python -m pytest tests/test_phase4_auth_integration.py -v
```
