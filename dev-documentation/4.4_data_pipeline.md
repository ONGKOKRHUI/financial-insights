## Current data flow

1. **Scraper** (`main.py`): Playwright + stealth; `COMPANY_CONFIG` drives which modules run and which `(year, quarter)` tuples are missing under `src\scraper\data\raw\{COMPANY}\{COMPANY}_{YEAR}_{Q}.pdf`. Skips existing files (idempotent backfill); `--latest` limits to “current completed quarter.”  
2. **Scheduler** (`scheduler.py`): Runs `main.main(latest_only=True)` on startup and weekly Mondays 09:00; optional commented Sunday full backfill.  
3. **ETL (intended production path)** (`finsight_etl_dag.py`):  
   - `get_unprocessed_pdfs(RAW_DIR)` vs `pipeline_runs.status = 'success'`  
   - For each PDF: `mark_processed(..., processing)` → `run_pipeline(pdf_path)` → XCom payloads → `upsert_report(payload)` → `mark_processed(..., success|error)`  
4. **`run_pipeline`** (`graph.py`): Default **`PIPELINE_ENGINE=langgraph`**: `parse_pdf` → `route_content` → parallel `extract_quantitative` / `extract_qualitative` → `merge_and_validate`. Alternate **`PIPELINE_ENGINE=dify`**: parse only, then Dify workflow.  
5. **Parse**: LlamaCloud `AsyncLlamaCloud` when `LLAMA_CLOUD_API_KEY` is set; otherwise PyMuPDF (`parser.py`). Docs describe `parsing_instruction` for Markdown tables; current `parser.py` snippet in search shows `tier="agentic"` and `expand=["markdown_full"]` — compare with docs if HTML tables appear.  
6. **Metadata**: From filename `{TICKER}_{YEAR}_{PERIOD}.pdf` in `_extract_metadata_from_path` (`parser.py`).  
7. **Persistence**: `loader.py` upserts **five financial tables** + maintains **`pipeline_runs`**. Financial rows keyed by **`(ticker, fiscal_year)`** — same key for all quarters if `fiscal_year` is only the year digit from the filename (see gaps below).

## Missing or fragile integration points

- **Scraper ↔ pipeline**: No code path in the scraper invokes `run_pipeline` or the loader; ingestion assumes **Airflow (or a manual script)** scans `FINSIGHT_RAW_DIR` (default `...\src\scraper\data\raw`). Local dev without Airflow needs a manual loop or cron.  
- **Quarter vs DB grain**: Loader and ORM use **`fiscal_year` only** for income/balance/cash/kpi/qualitative. Filenames encode quarter (`Q1`…`Q4`), but merger uses **`fiscal_year` from the middle segment** (`parser.py`). Multiple quarters in the same calendar year likely **overwrite** the same `(ticker, fiscal_year)` row unless extraction maps quarters differently — worth validating against product intent.  
- **`companies` vs loader**: `upsert_report` writes child tables with FK to `companies.ticker`. **No loader step inserts `Company`**; tickers must already exist (e.g. from seed) or inserts can fail on FK.  
- **`mock_data.py`**: `seed.py` imports `from data.mock_data import ...` (expected under `src/backend/` working dir). **No `mock_data.py` showed up in workspace search** — it may be gitignored, not committed, or missing clone artifact; backend seed would fail until present.  
- **Alembic vs core schema**: Only **`users`, `refresh_tokens`, `api_keys`** are migrated. **`companies` + financial tables** are implied to come from **`Base.metadata.create_all`** at startup (`main.py` pattern); align deployments accordingly.  
- **`pipeline_runs` paths**: Tracking uses absolute paths from `get_unprocessed_pdfs`; consistency across machines/job runners matters.
