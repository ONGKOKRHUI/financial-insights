## Current route structure

- **`/companies`** — Server component; lists companies from the backend (via server-side `fetch` to `${INTERNAL_API_URL \| NEXT_PUBLIC_API_URL}/companies`). Uses `CompanyCard` → `/companies/[id]`.
- **`/companies/[id]`** — Server component; hits FastAPI directly for company, summary, and income statement; public charts (RevenueTrend, IncomeBar, Margin, FinancialsTable).
- **`/`** — Client “hub” for authenticated users; role-based grid (hardcoded `COMPANIES`). Paid/admin tiles link to **`/dashboard/[ticker]`**; free tier shows non-link tiles + upgrade CTA.
- **`/dashboard`** — Server redirect to **`/`** (`redirect("/")` in `dashboard/page.tsx`).
- **`/dashboard/[ticker]`** — Client page; Pro charts; fetches **`/api/financials/[ticker]`** and **`/api/companies/${ticker}/summary`** (see data note below).

Middleware treats **`/companies` and `/companies/**`** as public (`PUBLIC_PATHS` + `pathname.startsWith(p + "/")`). **`/api/**`** is excluded from the middleware matcher, so BFF enforces auth where implemented per route.

## Auth logic (cookie, middleware, roles)

1. **Middleware** (`middleware.ts`): Decodes JWT payload from `access_token` **without** verifying the signature (documented as UX-only).  
   - Unauthenticated: `/` → `/companies`; other protected paths → `/auth/login?redirect=…`.  
   - `/auth/*`: logged-in users → `/`.  
   - **`/dashboard/**`**: requires `role === "paid"` **or** `"admin"`; else → `/upgrade`.  
   - **`/admin/**`**: requires `"admin"`; else → `/`.  
   - **`/account/**`**: requires authentication (falls through after global auth gate).  

2. **Client**: `SessionHydrator` in `providers.tsx` runs `useCurrentUser()` → `GET /api/auth/me` → Zustand `authStore` (`free` \| `paid` \| `admin`).

3. **Sign-out**: `useLogout` posts to `/api/auth/logout`, clears store and React Query cache, **`router.push("/auth/login")`** (does not send users to `/companies`).

4. **`/dashboard/[ticker]` breadcrumb**: “Dashboard” links to **`/dashboard`**, which **redirects to `/`**, not to a company picker — acceptable but worth knowing.

5. **Header vs comments**: `Header.tsx` comment claims paid users get **“Pro Analytics”** nav; **implemented** nav adds **Upgrade** (free) and **Admin** (admin), but **no dedicated “Pro Analytics” link for `paid`**.
