## What I checked and fixed

Your idea was correct, but I found a few issues in local Airflow setup and fixed them:

1. **Airflow dependency installation**
  - Before: only `airflow-init` installed Python deps at runtime; webserver/scheduler could miss pipeline libs.
  - Now: added `**Dockerfile.airflow`** and switched Airflow services to `build` from it, so all services have the same dependencies.
2. **Startup ordering**
  - Before: webserver/scheduler could start before `airflow-init` finished migration/user creation.
  - Now: `airflow-webserver` and `airflow-scheduler` depend on `airflow-init` with `service_completed_successfully`.
3. **Fernet key robustness**
  - Added a non-empty default `AIRFLOW__CORE__FERNET_KEY` in compose and `.env.example`.
4. **DB connectivity for Airflow containers**
  - Added support for `AIRFLOW_DATABASE_URL` in `docker-compose.airflow.yml`:
    - `DATABASE_URL: ${AIRFLOW_DATABASE_URL:-${DATABASE_URL:-postgresql://postgres:postgres@postgres:5432/finsight}}`

## How to switch pipelines locally

You have two separate “switches”:

### A) Switch **orchestrator** (deployment-like vs Airflow)

- **Deployment-like/local cron style:** run `src/scraper/scheduler.py` (weekly ingestion path)
- **Airflow style:** run Docker Airflow stack and DAG

### B) Switch **ETL engine** used by pipeline (`run_pipeline`)

- In `.env` set:
  - `PIPELINE_ENGINE=langgraph` (Gemini + LangGraph)
  - `PIPELINE_ENGINE=dify` (Dify workflow path)
- Restart Airflow containers after changing env:

```bash
docker compose -f docker-compose.airflow.yml down
docker compose -f docker-compose.airflow.yml up -d --build
```

## ML Features ETL DAG (`ml_features_etl`)

A second Airflow DAG computes **19 populated ML training metrics** (of 21 schema
columns) weekly into the `predictive_features` PostgreSQL table.

| Property | Value |
|----------|-------|
| DAG ID | `ml_features_etl` |
| File | `dags/ml_features_etl_dag.py` |
| Schedule | `0 1 * * MON` (Monday 09:00 MYT) |
| Tasks | `discover_feature_targets` → `run_feature_pipeline` → `load_feature_payloads` |

**Data sources (no FMP API):** yfinance, TradingView sector screener,
Investing.com earnings, i3investor KLSE HTML, Malaysia Warrants IV.
Peer sentiment uses a fast Investing.com peer pass first, then bounded slow
fallback only when the fast pass is undersampled.

**Required env vars:** `DATABASE_URL`. Optional: `ML_FEATURE_TICKERS`,
`ML_FEATURE_YEAR`, `ML_FEATURE_QUARTER`, `ML_FEATURE_LIMIT`,
`ML_PEER_SENTIMENT_SAMPLE_LIMIT`, `ML_PEER_SENTIMENT_MIN_RATES`,
`ML_PEER_SENTIMENT_FALLBACK_LIMIT`.

Local smoke test:

```bash
docker compose -f docker-compose.airflow.yml exec -T airflow-webserver \
  airflow dags test ml_features_etl 2025-01-06
```

Fast validation (cap tickers):

```bash
ML_FEATURE_LIMIT=2 docker compose -f docker-compose.airflow.yml exec -T airflow-webserver \
  airflow dags test ml_features_etl 2025-01-06
```

Manual CLI run (no Airflow):

```bash
cd src/scraper
python ml_pipeline_runner.py --tickers MAYBANK,CIMB --fiscal-year 2025 --fiscal-quarter Q4
python ml_pipeline_runner.py --dry-run   # inspect payloads, no DB writes
```
